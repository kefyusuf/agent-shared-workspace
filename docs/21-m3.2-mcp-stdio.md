# M3.2 — MCP stdio adapter over authenticated local broker

**Status:** protocol/wire compatibility demonstrated with real stdio subprocesses and the real local HTTP broker. **Codex and Claude Code CLIs have NOT been executed in this test environment.** Provider-specific compatibility is therefore unverified. PR remains subject to review and security gate.

## Scope

MCP stdio, `initialize` + `notifications/initialized`, `ping`, `tools/list`, `tools/call` with JSON-RPC 2.0 on newline-delimited UTF-8; protocol version pinned to handshake-era `2025-11-25`. A 2026-era `server/discover` probe produces Method not found so auto-negotiating clients can fall back to the classic initialize handshake. **No claim of 2026-07-28 native protocol support.**

The adapter holds **one agent credential per process** and signs in to the HTTP broker over explicit IPv4 loopback using `/v1/session`. The issued bearer token is never printed and is used only on allowlisted `/v1/call` operations. No generic URL, arbitrary method, filesystem, SQL, enrollment, bootstrap, operator, completion-override, or provider-session access tool exists.

## Trusted setup and CLI examples

Run from a checkout containing the M3.2 files. Store the local database outside tracked files or under ignored `.local/`.

```sh
export PYTHONPATH=src
python -m agent_workspace.broker init --db .local/workspace.db --name "Example" --root .
python -m agent_workspace.broker serve --db .local/workspace.db --port 8765
```

`init` prints the operator credential *once*. Protect it in a local secret manager. In a second trusted terminal:

```sh
export PYTHONPATH=src
python -m agent_workspace.operator_cli enroll --db .local/workspace.db --name codex --provider codex
python -m agent_workspace.operator_cli enroll --db .local/workspace.db --name claude --provider claude
```

Operator CLI prompts for an operator credential without putting it in command arguments. Each enrollment displays an **independent** agent credential exactly once. Store these separately, avoid shell histories, repositories, and log output. The trusted local operator CLI directly accesses SQLite by design; **MCP adapters never do**.

Set environment variables *in the agent process environment*, injected from your local secret store:

- `AW_AGENT_CREDENTIAL`: the **individual agent's** credential, not the operator credential.
- `AW_BROKER_PORT`: local broker port (default `8765`). Host is **fixed to 127.0.0.1**, cannot be configured to external URLs.
- `PYTHONPATH`: absolute path to this repository's `src` (or install the project in a venv).

The MCP server command is:

```sh
python -m agent_workspace.mcp_stdio
```

Example illustrative *stdio MCP host* config (host-specific formats vary; no secrets in file):

```json
{
  "mcpServers": {
    "agent-workspace": {
      "command": "python",
      "args": ["-m", "agent_workspace.mcp_stdio"]
    }
  }
}
```

The MCP host must inherit or securely inject the environment variables. Start a separate MCP adapter process for every agent; never share credentials across agent processes. Do not put an `AW_AGENT_CREDENTIAL` literal in versioned configuration. On Windows use `py -m agent_workspace.mcp_stdio`, and set env via PowerShell process environment or your secret manager.

| Identity | `workspace_identity` |
| Tasks | `task_list`, `task_get`, `task_claim`, `task_renew`, `task_release` |
| Mailbox | `mail_inbox`, `mail_send` |
| Brain / Memory | `brain_brief`, `memory_search`, `memory_record` |

The operator creates tasks using the existing trusted domain API, not MCP. Updates, approvals and evidence-review actions remain gated; this iteration only exposes a minimal subset needed for a handoff pilot. Task claims use expected version and idempotent request keys; context publication requires an active lease and fencing token. Sending a handoff does not transfer lease ownership. Memory is agent-reported, not promoted to the accepted Brain.

## Trust boundaries

- The HTTP broker remains authoritative for role-based permissions, idempotency, source privacy, lease fencing and audit.
- Invalid or revoked sessions stop tool calls, even when MCP tool discovery remains available.
- MCP traffic on stdout contains only JSON-RPC. Credential and raw exception text never appear in protocol responses.
- A malicious or compromised **same-OS-user** coding agent can still read local DB files accessible to that user. An HTTP broker **is not an OS sandbox**; dedicated OS identities and restricted SQLite file permissions are required for stronger separation. Windows ACL setup is not included.
- Operator CLI prints issued agent credentials to the trusted terminal for one-time capture, not to MCP.
- Handoff summaries are untrusted text with no automatic secret filter or prompt-injection defense.
- Provider native session history, actual live CLI process management, background push notifications, token-cost measurements, a Kanban dashboard and a 2026-native MCP server are out of scope.

## Verification

`PYTHONPATH=src python -m unittest discover -s tests -v` verifies existing domain/broker tests plus protocol handshake, strict JSON-RPC, unauthorized/malformed operation rejection, broker revocation, two separate stdio clients using real localhost HTTP, message visibility, memory read/write and task snapshot-handoff/lease handover. Local test success is distinct from live Codex or Claude Code compatibility. Do not merge an unreviewed stacked PR merely because unit tests pass.
