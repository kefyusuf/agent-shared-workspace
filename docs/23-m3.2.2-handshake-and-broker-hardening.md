# M3.2.2 — Handshake Compatibility and Broker Idle Timeout

## Scope

This is a narrowly scoped M3.2 pre-provider compatibility hardening change. It does not add MCP 2026-07-28 stateless mode, a background scheduler, a UI, new database tables or native agent-session access.

## Handshake negotiation

The stdio adapter now explicitly echoes the offered handshake version if it is one of `2024-11-05`, `2025-03-26`, `2025-06-18`, or `2025-11-25`. For other nonempty version strings, it counteroffers `2025-11-25`; it never claims to support the modern `2026-07-28` stateless lifecycle. A blank version is a validation error, and a rejected initialize request does not advance the server lifecycle.

MCP stdio remains newline-delimited JSON-RPC and is tested with independent subprocesses over the authenticated HTTP broker. Negotiated older revisions use the same narrow MCP tool surface, and actual Codex/Claude Code interoperability has not been demonstrated.

## Local broker read timeout

Each accepted HTTP connection has a 2.0-second **socket idle timeout**. A client that declares a nonempty request body but stops transmitting receives HTTP 408 with a stable `REQUEST_TIMEOUT` code rather than leaving a worker indefinitely blocked on the missing bytes. This protects against stalled idle connections. It is **not an absolute wall-clock request deadline**, a comprehensive slowloris defense, a per-principal rate limiter, or a substitute for OS isolation or a front proxy.

## Test-first evidence

- RED: version negotiation regressions demonstrated incorrect `2025-11-25` echoes for supported older versions; empty version was accepted. An incomplete Content-Length body held the worker until the test client's timeout.
- GREEN: handshake tests cover old and current revisions, modern counteroffer and invalid blank version; a real socket test verifies HTTP 408 and continued availability of a separate health request.
- Full test suite and Python 3.11/3.13 CI must pass before review or merge. Run `PYTHONPATH=src python -m unittest discover -s tests -v`.

## Open acceptance gates

- Actual Codex CLI and Claude Code CLI must each invoke the adapter on the user's own machine and produce redacted results.
- Independent review of PR #1 through the stacked follow-up PRs, security boundaries, and branch CI is required before merge.
- Same-user untrusted processes still can bypass domain permissions by accessing SQLite directly; no production-security assertion.
